Methodology memo

How this radar is built, and what it cannot say

Thesis

A protocol that holds large value, keeps growing, and has run for a long time without a token is the likeliest kind of protocol to launch one — and the market already prices that kind of protocol, through the tokens that trade in its category. So the radar prices every pre-token protocol by the category's own median market-cap-to-TVL ratio, adjusted for its growth, its age, and its footprint. One formula, every protocol alike, no name ever special-cased. Protocols whose token already trades never appear on the board: they are the calibration set only, the board is the protocols still to come.

Worked example

Limitations, stated plainly

  • The snapshot is frozen: TVL, growth and prices are one day's record, not a forecast. A protocol can halve in a week.
  • A median multiple is a category's middle, not a promise for any one protocol. The interquartile range beside each multiple shows how wide the category's own ratios run.
  • Nothing here predicts whether or when a protocol issues a token. Some never will; some record no token only because the record misses one.
  • Farm-plan costs are gas estimates for ordinary transactions; congestion moves them, and bridge tolls sit outside the totals. Times are active work across an 8–12 week horizon, including weekly checks.
  • TVL can be gamed, borrowed, or double-counted across chains. The signals on each row flag what the model did not know.

How to audit this page

Every number here is computed in this dossier's own code from the sealed snapshot — the board by the builder, the playground and the checks by the page itself. Nothing is pasted, nothing is fetched. The recompute check above re-derives every submitted value from the snapshot's figures; each row's detail view shows its own arithmetic, its nearest live-token comparables, and the cost and time of every farm step. Say a protocol records no token, never that it has none: a record can miss a token that exists.
