How the radar works

The value model

Every implied value is computed from the snapshot's own figures, by one formula applied to every protocol alike. The category multiple is the median market-cap-to-TVL ratio of the protocols in the same category whose token already trades; categories with fewer than three such protocols use the global median, and the calibration table marks them. The growth factor follows the seven-day TVL change, clamped so one wild week cannot dominate. The maturity factor follows the days since listing, saturating past the first year. The footprint factor follows the number of chains, capped at eight extra chains.

No protocol name is ever special-cased: the same formula ranks every protocol on the board. Protocols whose token already trades never appear on the board. They are the calibration set only — the board is the protocols still to come, separated from the ones that already trade.

Reading a row: click it for the value breakdown, the reason it ranks where it does, the data signals behind it, and its farm plan. The check line under the breakdown recomputes the implied value from the snapshot's figures, so the arithmetic can be verified without trusting the table.

What counts as pre-token

A protocol records no token when both gecko_id and symbol are null in the snapshot. The board also leaves out wrapped, staked and bridged products of tokens that already trade, by the same exclusion the snapshot's own watchlist rule applies. Say a protocol records no token, never that it has none: a record can miss a token that exists.

Limits of this radar. The snapshot is frozen: prices, TVL and growth are one day's record, not a forecast. A median multiple is a category's middle, not a promise for any one protocol. Nothing here predicts whether or when a protocol issues a token. Implied values are this entry's own claim, never make.fun's. Farm plans are starting points, not financial advice; check every step against the protocol's own pages before moving funds.
